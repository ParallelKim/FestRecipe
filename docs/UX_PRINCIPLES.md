# FestRecipe UX 원칙 — 본질에 집중하기

> 이 문서는 FestRecipe 인터페이스를 설계·수정할 때 따르는 **구조와 상호작용의 기준**입니다. 문장·용어는 [`TONE_AND_MANNER.md`](./TONE_AND_MANNER.md)를, 화면 계층·섹션·행동은 이 문서를 따릅니다.

---

## 1. 한 줄 원칙

**화면에 올린 것은 사용자가 지금 하려는 일의 본질이어야 한다.**  
부가 기능·교차 탐색·상태 안내는 본질을 가리거나 사이에 끼어들면 안 된다.

FestRecipe의 본질은 카피 가이드와 같다: **예습(대표곡)** · **선택(타임테이블)** · **계획(내 라인업·배경화면)**.  
한 화면·한 시트·한 카드는 이 중 **하나의 일**을 중심으로 두고, 나머지는 그 일을 방해하지 않는 자리에 둔다.

---

## 2. 정보 계층 = 사용자 과업

컨트롤이 가깝다고 같은 덩어리로 묶지 않는다. **같은 질문에 답하는 요소끼리** 묶는다.

| 과업 | 사용자가 묻는 것 | 같이 묶을 것 | 끼워 넣지 말 것 |
|------|------------------|--------------|-----------------|
| 아티스트 맥락 | "이 사람이 누구고, 내 계획에 넣었나?" | 이름, 담기/담김, 내 라인업으로 가기 | 곡 목록·듣기 CTA |
| 대표곡 | "뭘 듣고, 어떤 곡이 있지?" | 곡 수 메타, YouTube로 듣기, 곡 목록 | 담기·내 라인업 |
| 내 라인업 | "오늘 누구를 담았고, 어떻게 듣지?" | 담은 목록, 비우기, 모아 듣기, 배경화면 | 단일 아티스트 상세를 같은 카드에 섞기 |
| 타임테이블 | "언제 어디서 누구지?" | 슬롯·스테이지·내 라인업 강조 | 긴 설명 바·중복 범례 |

### 잘못된 계층 (하지 말 것)

```
[아티스트 이름]
[회색 카드]
  메타
  YouTube로 듣기      ← 대표곡
  담기 | 내 라인업    ← 계획 기능이 대표곡 흐름을 끊음
[/카드]
대표곡 목록             ← 듣기와 목록이 시각적으로 분리됨
```

듣기와 곡 목록은 **한 과업(대표곡)** 인데 카드·구분선으로 갈라지고, 그 사이에 **다른 과업(계획)** 이 끼면 계층이 틀린 것이다.

### 올바른 계층

```
[← 이전]          [내 라인업]     ← 탐색·계획 (헤더)
아티스트명         [☆ 담기]       ← 아티스트 맥락

대표곡 N곡 · YouTube              ← 여기부터 대표곡 섹션
[YouTube로 듣기]
1. 곡 …
2. 곡 …
```

- **탐색·담기**는 이름과 같은 층(헤더·아이덴티티).
- **듣기·목록**은 한 섹션. 카드로 듣기만 감싸 목록과 끊지 않는다.
- 같은 라벨을 헤더와 본문에 두 번 쓰지 않는다(이름·「대표곡 목록」 중복 등).

## 3. 본질을 지키는 세부 규칙

### 3.1 한 섹션 · 한 일

섹션(카드, 패널, 시트 뷰)마다 **목적 하나, 제목 하나, 짧은 보조 문장(필요 시) 하나**를 넘기지 않는다.  
「있으면 좋은」 버튼·링크·뱃지를 그 섹션 한가운데에 끼우지 않는다. 다른 과업이면 **위·아래 다른 구역** 또는 **다른 뷰(탭)** 로 보낸다.

### 3.2 설명보다 구조

레이아웃이 바뀌며 나타나는 안내("N팀 · 타임테이블에 표시돼요")는 구조를 흔들고 본질을 흐린다.  
이미 시각(슬롯 강조)·카운터(내 라인업 N)·담기 토글로 이해되면 **문구를 추가하지 않는다.**  
안내가 꼭 필요하면 **항상 같은 자리**에 두거나, 빈 상태에만 다음 행동을 적는다. ([`TONE_AND_MANNER.md`](./TONE_AND_MANNER.md) 빈 상태 규칙)

### 3.3 레이아웃은 흔들리지 않게

상태 전환(담기↔담김, 준비됨↔준비 중)으로 **높이·너비가 늘어나 아래 콘텐츠가 밀리면** UX가 깨진다.

- 조건부 블록을 끼워 넣지 말고, **같은 슬롯**에서 라벨·스타일만 바꾼다.
- 없어질 수 있는 버튼은 `visibility`/`disabled`로 자리를 지키거나, 처음부터 항상 보이는 한 줄로 둔다.
- 「담기 후에만 생기는 두 번째 줄」 같은 패턴을 피한다.

### 3.4 시트·패널 내비게이션

모바일 바텀 시트처럼 **뷰가 여러 개인 컨테이너**에서는:

- 현재 뷰가 무엇인지 **헤더(탭·뒤로가기)** 로 드러낸다.
- 「닫기」가 시트 전체 닫기인지, **이전 뷰로 돌아가기**인지 섞지 않는다. 아티스트 상세의 기본은 **이전 뷰**.
- FAB는 새 맥락을 강요하기보다, 가능하면 **마지막에 보던 허브/라인업**을 복원한다.
- **같은 액션을 두 UI에 두지 않는다.** 예: 모바일에서 대표곡·내 라인업 진입은 FAB·시트 탭만, 타임테이블 위 바 허브는 쓰지 않음. 라인업에서 열린 아티스트는 `← 내 라인업`만, 우측 「내 라인업」 링크는 대표곡 탭에서만.

### 3.5 장식용 구획을 만들지 않는다

테두리·배경 카드는 **상호작용 단위**이거나 **과업이 바뀌는 경계**일 때만 쓴다.  
카드 안에 A를 넣고 카드 밖에 A의 연속을 두면, 사용자는 A와 A'를 다른 일로 읽는다. 본질이 같으면 **같은 평면**에 둔다.

## 4. 적용 사례 (아티스트 대표곡 시트)

2026-07-29 피드백으로 확정한 구조. 새 화면을 만들 때 기준으로 삼는다.

| 층 | 역할 | UI |
|----|------|-----|
| 모바일 진입 | 듣기·라인업 한곳 | FAB → 시트 탭(대표곡 / 내 라인업) |
| 시트 헤더 네비 | 어디로 갈지 | `← 대표곡` 또는 `← 내 라인업` · (대표곡에서만) `내 라인업` 링크 |
| 시트 헤더 아이덴티티 | 누구인지·담았는지 | 아티스트명 + `☆ 담기` |
| 본문 대표곡 섹션 | 무엇을 들을지 | 메타 → 듣기 CTA → 곡 리스트 (한 덩어리) |

관련 구현: `PlaylistMobileDock.tsx`, `ArtistPlaylistPanel.tsx` (`playlist-artist-identity` / `playlist-artist-songs`).

### 4.1 모바일 예상 플로우 (예습·선택·계획)

FestRecipe 정체성([`TONE_AND_MANNER.md`](./TONE_AND_MANNER.md) §1)에 맞춘 **주요 경로**입니다. UI는 이 흐름을 방해하지 않게 한 진입점·한 제목을 유지합니다.

| 가치 | 사용자 상황 | 기대 행동 | UI 진입 |
|------|-------------|-----------|---------|
| **예습** | 모르는 아티스트가 많다 | 타임테이블·라인업에서 **한 팀** 곡 듣기 | 슬롯·칩 탭 → 시트 **아티스트** 뷰 |
| **예습** | 오늘·전체를 한번에 듣고 싶다 | **날짜·페스티벌** 묶음 재생 | **듣기** FAB → **대표곡** 탭 버튼 |
| **선택** | 시간이 겹친다 | 들으며 비교 → ☆ 담기 | 타임테이블 + 시트 아티스트 뷰 **담기** |
| **계획** | 내가 볼 무대만 모으고 싶다 | ☆로 담기 → 모아 듣기·배경화면 | 타임테이블 ☆ 또는 FAB → **내 라인업** 탭 |

**FAB(`듣기`)의 역할:** 타임테이블을 누르지 않고 **묶음 듣기·내 라인업** 허브를 열 때 쓴다. 아티스트 상세는 타임테이블·라인업 탭이 먼저이고, FAB는 보조 진입점이다.

**시트 대표곡 탭 구조:** 탭 제목 = 「대표곡」. 본문 = 날짜·전체 **듣기 버튼** + (비어 있을 때) 타임테이블 안내. 「대표곡 듣기」 라벨·「내 라인업」 칩·「아티스트 대표곡」 제목은 **탭과 중복**이므로 시트 안에서는 넣지 않는다.

## 5. UI 변경 체크리스트

구조·인터랙션을 바꾸는 PR은 머지 전에 확인한다.

- [ ] 이 섹션의 **한 가지 과업**이 문장으로 말해지는가?
- [ ] 그 과업과 무관한 컨트롤이 **과업의 한가운데**에 끼어 있지 않은가?
- [ ] 같은 과업의 요소(예: 듣기 + 목록)가 **한 시각 덩어리**인가?
- [ ] 이름·제목이 **두 번** 반복되지 않는가?
- [ ] **같은 액션**을 하는 버튼·탭·링크가 화면에 **두 군데** 있지 않은가?
- [ ] 상태 전환 시 **레이아웃 시프트**가 없는가?
- [ ] 「설명 문구」가 구조·시각으로 이미 전달되는 내용을 중복하지 않는가?
- [ ] 시트/모달에서 **닫기 vs 뒤로**가 사용자 기대와 맞는가?
- [ ] 카피 변경이 있다면 [`TONE_AND_MANNER.md`](./TONE_AND_MANNER.md)도 통과하는가?
