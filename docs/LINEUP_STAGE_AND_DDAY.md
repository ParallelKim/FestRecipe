# 라인업 공개 단계 UI · D-day — 보류·복원 메모

> **상태:** 상세 페이지의 **「공개 진행 상황」(1→2→3단계)** UI는 제거했다.  
> 추후 **D-day / 공개 카운트다운** 등과 함께 복원할 수 있도록 카피·구조만 남긴다.  
> `lineupStage` 필드는 **뷰 분기용 데이터**로 계속 사용한다 (UI 진행 바와는 별개).

관련: 예상 셋리스트 복원 → [`SETLIST_RECIPE.md`](./SETLIST_RECIPE.md)

---

## 1. 왜 숨겼는가

- 이미 `stage3_timetable`인 페스티벌에서 단계 바가 정보 밀도만 높이고 가시성을 해침
- 모바일 첫 화면에서 타임테이블·플레이리스트보다 우선순위가 낮음
- D-day·티켓/공개 알림과 묶을 때 다시 설계하는 편이 낫다

---

## 2. 구 UI 카피 (복원용)

섹션 제목: `공개 진행 상황`

| 단계 | 라벨 | 활성 시 표시 |
|------|------|-------------|
| `stage1_all` | `1단계 전체 라인업` | `✓` |
| `stage2_daily` | `2단계 일별 라인업` | `✓` |
| `stage3_timetable` | `3단계 타임테이블` | `✨` |

연결 화살표: `→`  
홈 카드 뱃지(구): `1단계: 전체 라인업` / `2단계: 일별 라인업` / `3단계: 타임테이블`  
홈 카드 뱃지(현): `전체 라인업` / `일별 라인업` / `타임테이블` (단계 숫자 없음)

구현 참고 커밋: `354112b` (`ui: 공개 진행 상황(n단계) 섹션 제거`) 직전 `FestivalDetail.tsx`

---

## 3. 데이터 모델 (유지)

```ts
export type LineupStage = 'stage1_all' | 'stage2_daily' | 'stage3_timetable'

// Festival.lineupStage 로 상세 뷰 분기:
// - stage1_all      → 전체 아티스트 칩
// - stage2_daily    → 일별 아티스트 그리드
// - stage3_timetable → DayTabs + TimetableGrid
```

이 필드는 **진행 바 UI 없이도** 필요합니다.

---

## 4. D-day와 같이 복원할 때 제안

한 섹션으로 합치지 말고, 역할이 다른 두 블록으로 분리:

1. **D-day / 일정 티커** (항상 유용)  
   예: `D-12 · 7.31 FRI 개막` / 입장·폐막 시각
2. **공개 단계** (라인업이 아직 덜 열렸을 때만)  
   `stage3`이면 숨기거나 “타임테이블 공개됨” 한 줄로 축약

카피 톤 가이드:
- 스폰서·스테이지 열거는 진행 바에 넣지 말 것 (타임테이블 헤더에만)
- 히어로는 `tagline` 위주, 긴 `description`은 SEO·하단용

---

## 5. 페스티벌 설명 필드 가이드

| 필드 | 용도 | 넣지 말 것 |
|------|------|-----------|
| `tagline` | 히어로·홈 카드 한 줄 | 스폰서단 스테이지명, 장황한 주최 문구 |
| `description` | SEO·스키마·보조 설명 | 스테이지 스폰서 나열 (KB·몬스터·스탠리 등) |

스테이지명은 **타임테이블 컬럼 헤더**에만 둔다.
