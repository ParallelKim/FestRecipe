# FestRecipe 제품 원칙

코드와 카피가 흔들릴 때 돌아가는 **불변에 가까운 기준**만 적는다.  
구현 스냅샷·세션 핸드오프·벤치마크 조사는 문서로 쌓지 않는다.

## 한 줄

페스티벌 가기 전에 **예습(대표곡)** · **선택(타임테이블)** · **계획(내 라인업·배경화면)** 을 돕는 준비 도구.

음악 스트리밍 앱이 아니다. 짧게 들러 정보를 훑고 **듣기·담기**로 끝낸다.

## MVP 경계

| 한다 | 하지 않는다 |
|------|-------------|
| 라인업 단계(전체 / 일별 / 타임테이블)에 맞는 UI | 예상 셋리스트·풀캠 타임스탬프·앱 내 재생 |
| YouTube로 대표곡 핸드오프 | YouTube Music 전용 UI·시스템 컬러 피커 |
| 내 라인업(☆) · 배경화면 PNG | 계정 동기화(추후) |

`lineupStage`는 **뷰 분기 데이터**로 유지한다. 공개 진행 바 UI는 두지 않는다.

## 대표곡

- **아티스트 단독:** YTM 인기순 대략 10~20곡 (`tracks` 전체).
- **번들(요일·페스티벌·내 라인업):** 티어별 `targetSongCount`(3~5)만.
- 듣기 카피·링크는 **YouTube**로 통일.

## 배경화면

- PNG 기본 내용: **배경색 + 타임테이블만** (워터마크·긴 설명 없음).
- 캡션(페스티벌명·날짜)은 **선택, 기본 OFF**. 이름은 `shortName` 우선(대문자 권장).
- 메인 타임테이블과 **같은 그리드**를 축소해 넣는다. 전용 재레이아웃 금지.

## 아티스트 표기

화면용 `name`은 사람이 검수한다. 원칙은 [`ARTIST_DISPLAY_NAMES.md`](./ARTIST_DISPLAY_NAMES.md).

## 카피

[`TONE_AND_MANNER.md`](./TONE_AND_MANNER.md) — 해요체, 용어 사전, 버튼·빈 상태 규칙.

## SEO

[`SEO.md`](./SEO.md) — Helmet + 빌드 시 prerender·sitemap. 카피는 톤앤매너를 따른다.

## UI 구현 원칙 (짧음)

1. **shadcn 우선** — 레이아웃은 Tailwind `className`, 외형은 variant·시맨틱 토큰.
2. **타임테이블만** CSS Module (`MobileTimetable.module.css`) — 절대 배치·스테이지 변수·export 모드.
3. 글로벌 CSS는 **토큰(`@theme`)·베이스**에 한정한다.
