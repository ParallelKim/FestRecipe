# FestRecipe 톤앤매너 가이드

> 이 문서는 FestRecipe의 모든 사용자 대면 텍스트(UI 카피, 안내문, 오류 메시지, SEO 문구)가 따라야 할 목소리의 기준입니다. 새 텍스트를 추가하거나 기존 텍스트를 고칠 때 이 가이드를 먼저 확인하세요.
>
> **레퍼런스·벤치마킹**은 [`UI_REFERENCE_RESEARCH.md`](./UI_REFERENCE_RESEARCH.md)를 참고합니다. 카피는 예습·선택·계획 가치를 공유합니다.

---

## 1. 서비스가 제공하는 가치

FestRecipe는 **페스티벌 관객의 사전 준비 도구**입니다. 관객이 이 서비스에서 얻는 가치는 세 가지입니다.

| 가치 | 사용자의 질문 | 서비스의 답 |
|------|--------------|-------------|
| **예습** | "모르는 아티스트가 많은데, 뭘 들어보지?" | 라인업 아티스트의 대표곡을 미리 들려준다 |
| **선택** | "시간이 겹치는데 누구를 볼까?" | 타임테이블과 대표곡을 나란히 보여 판단을 돕는다 |
| **계획** | "내가 볼 무대만 정리해 두고 싶어" | 내 라인업 담기와 배경화면 저장으로 현장에서 쓸 수 있게 한다 |

사용자는 페스티벌을 앞두고 **기대감을 가지고 가볍게 들르는** 20~30대 관객입니다. 음악 앱을 켜듯 짧게 방문해, 빠르게 정보를 훑고 행동(듣기·담기)합니다. 업무 도구가 아니라 **놀러 갈 준비를 하는 맥락**임을 잊지 마세요.

---

## 2. 목소리의 정의

FestRecipe의 목소리는 **"같이 준비하는 동료 관객"**입니다.

- **친근하지만 절제되어 있습니다.** 감탄사와 과장("최고의 페스티벌!", "놓치지 마세요!")을 쓰지 않습니다. 설렘은 홍보 문구가 아니라 정확한 정보 안에 자연스럽게 담깁니다.
- **가르치지 않고 알려줍니다.** "~해야 합니다", "~하시기 바랍니다" 같은 지시·공문 말투를 쓰지 않습니다.
- **행동이 바로 이해되게 씁니다.** 사용자가 다음에 무엇을 하면 되는지 한 문장 안에 답이 있습니다.

### 목소리 예시

| 상황 | FestRecipe답지 않은 말 | FestRecipe다운 말 |
|------|------------------------|-------------------|
| 기능 안내 | "본 서비스는 타임테이블 이미지 저장 기능을 제공합니다." | "타임테이블을 배경화면으로 저장해요." |
| 빈 상태 | "데이터가 존재하지 않습니다." | "아직 담은 아티스트가 없어요." |
| 행동 유도 | "별표 버튼을 클릭하시기 바랍니다." | "☆를 눌러 담아 보세요." |
| 오류 | "요청을 처리할 수 없습니다." | "페스티벌을 찾을 수 없어요." |

## 3. 문장 규칙

### 3.1 종결어미 — 해요체로 통일

- **해요체("~해요", "~이에요")를 기본**으로 합니다.
- 합니다체("~합니다", "~됩니다")와 반말 명사형("~가 됨")은 쓰지 않습니다.
- 로딩·준비 중 같은 상태는 "~중" 형태를 허용합니다. ("불러오는 중…", "대표곡 준비 중")

### 3.2 컴포넌트 유형별 규칙

| 유형 | 규칙 | 예 |
|------|------|-----|
| **버튼** | 동사 원형 어미. 8자 이내 권장. 마침표 없음 | "담기", "YouTube로 듣기", "PNG 저장" |
| **화면·패널 제목** | 명사형. 마침표 없음 | "내 라인업", "배경화면 편집" |
| **안내문** | 한 문장 40자 이내, 최대 2문장. 하는 일 → 방법 순서 | "타임테이블에서 아티스트를 누르면 대표곡이 열려요." |
| **빈 상태** | 현재 상태 + 다음 행동 | "아직 담은 아티스트가 없어요. ☆를 눌러 담아 보세요." |
| **오류** | 무슨 일인지 + 사용자가 할 일 | "페스티벌을 찾을 수 없어요. 홈으로 돌아가 다른 페스티벌을 찾아보세요." |
| **로딩** | "불러오는 중…"으로 통일 | "페스티벌 정보를 불러오는 중…" |

### 3.3 표기·구두점

- 말줄임표는 "…"(U+2026) 하나로 통일합니다. 마침표 세 개("...")를 쓰지 않습니다.
- 안내문 문장 끝에는 마침표를 붙이되, 버튼·라벨·제목에는 붙이지 않습니다.
- 조사를 함부로 생략하지 않습니다. "배경화면만 할 수 있습니다" 같은 어색한 생략·나열을 피합니다.
- 능동형으로 씁니다. "클릭하세요"보다 "눌러 보세요".

### 3.4 외래어·기술 용어

사용자가 모를 수 있는 기술 용어는 쓰지 않거나, 쉬운 말로 바꿉니다.

| 금지 | 대신 |
|------|------|
| DPR | "기기 화면에 맞춤" |
| HEX 색상 코드 | "색상 코드" |
| YouTube Music | "YouTube" (실제 링크와 일치시킴) |
| 예상 셋리스트, 레시피(기능명) | "대표곡" |

"PNG"처럼 사용자가 파일 형식으로 인식 가능한 용어는 그대로 씁니다.

## 4. 용어 사전

핵심 개념은 반드시 아래 표기로 통일합니다. 같은 기능을 두 개 이상의 이름으로 부르지 않습니다.

| 개념 | 표기 | 쓰지 않는 말 |
|------|------|--------------|
| 사용자가 ☆로 고른 아티스트 목록 | **내 라인업** | 나만의 플레이리스트, 내가 고른 플레이리스트 |
| 아티스트의 대표곡 묶음 | **대표곡** | 대표 플레이리스트, 대표곡 플레이리스트, 예상 셋리스트 |
| 담는 동작 | **담기** (동작), **담김** (상태) | 고르기, 추가, 픽 |
| 듣는 동작 | **듣기** | 연속 재생, 재생, 플레이 |
| 배경화면 저장 기능 | **배경화면** | (첫 설명 시 "배경화면 타임테이블" 허용) |
| 아티스트를 여는 동작 | **누르기** | 선택, 클릭 |
| 페스티벌의 하루 단위 | **날짜** | 요일 |
| 서비스 한국어 명 | 필요 시 "FestRecipe" 그대로 | 페스트레시피 등 임의 번역 X |

## 5. 새 텍스트 추가 체크리스트

PR에 새 UI 텍스트가 포함된다면, 머지 전에 다음을 확인합니다.

- [ ] 용어 사전의 표기를 그대로 썼는가?
- [ ] 해요체인가? (합니다체·반말 명사형 혼입 없이)
- [ ] 안내문이 40자 이내 한두 문장인가?
- [ ] 버튼은 동사 원형 어미이고 마침표가 없는가?
- [ ] DPR·HEX 같은 기술 용어를 쓰지 않았는가?
- [ ] 빈 상태·오류에 "다음에 무엇을 하면 되는지"가 있는가?
- [ ] 말줄임표가 "…"인가?
- [ ] aria-label·title 같은 보이지 않는 텍스트도 같은 기준을 따르는가?
